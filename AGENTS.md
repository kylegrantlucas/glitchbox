# glitchbox — agent notes

macOS app (Glitchbox.app) that layers glitch plugins into chains, plus the seeded terminal pipelines it grew out of and `glitch-loop/`, an ffmpeg + FFglitch datamosh piece. Every tool ships inside the app bundle; there is no Nix. README.md is the product page (features, install, credits) and carries no development detail; the engineering facts live in this file, `packaging/build.sh`'s comments, and each pipeline's `--help` header.

## Layout
- `packaging/` — `build.sh [tools|app|dmg|all|verify]` builds the toolchain from `sources.json` (URL + sha256 per input), stages it in `build/stage/Contents`, builds the app/CLI, assembles `build/Glitchbox.app`, signs inside-out, verifies, and makes `build/dist/Glitchbox-<VERSION>.dmg`. Stages are stamped by recipe/input hash in `build/stamps`; downloads cached in `build/downloads`. Must stay runnable by `/bin/bash` 3.2. The `licenses` stage (needs `cargo-about` 0.9.2; `about.toml`/`about.hbs`) collects every component's licence texts into `Contents/Resources/licenses/<component>/` (upstream files, GStreamer's `share/licenses`, reactive-vcr's own notices, cargo-about crate lists for ntsc-rs-cli and bender, vendored `licenses/jq/COPYING`) and writes `Resources/Credits.html` (the About panel) from the `CREDITS` table; verify fails if a credited component has no texts. Adding a bundled tool means a `CREDITS` row and a `lic_copy` line.
- `app/` — `project.yml` (XcodeGen; generated `Glitchbox.xcodeproj` is gitignored; declares the MKV UTType for export), `Glitchbox/` (SwiftUI app, `AppIcon.icon` Icon Composer icon), `GlitchboxKit/` (engine library incl. `Export/` — `ExportPlan` pure argv builder, `Exporter`, `MediaProbe` — the `glitchbox` CLI, Swift Testing suite).
- Library: `plugins/*.json`, `presets/` (chains, `plugins/<id>/`, `vhs.json`, `reactive-vcr.toml`), `scripts/` (ffedit scripts), `pipelines/` (+ `_lib.sh`). Copied into `Contents/Resources/library` as the built-in, read-only library.
- Bundle: `Contents/Helpers/` (ffmpeg, ffprobe, ffgac, ffedit, fflive, qjs, ntsc-rs-cli, bender, reactive-vcr, jq, sox, bash, glitchbox), `Frameworks/GStreamer.framework`, `PlugIns/frei0r-1/*.dylib`, `Resources/{library,ffglitch-scripts,bender-presets,toolchain.json,licenses,Credits.html}`.
- `glitch-loop/` — standalone datamosh loop: a still (`source=`, default `glitch-loop/source.jpg`) → judder (`filters/judder.filter`) → MPEG-2 forced-MV (`ffgac`) → `ffedit` + `scripts/mv_average_timed.js` → VHS (`filters/vhs2.filter`) → `out/loop_mosh.mp4`. `combine` layers an external video over the tail and cross-moshes (`scripts/mv_layer_mosh.js`). Its justfile puts `../build/Glitchbox.app/Contents/Helpers` first on PATH. Intermediates go to `glitch-loop/work/`, finals to `glitch-loop/out/` (both gitignored; `out/` holds the owner's finished renders — don't delete). `source.jpg` is the owner's private image: gitignored, never committed (it was removed from all history), not MIT, never used for demos or site assets.
- `site/` — static splash page (no build step; relative URLs so it works from `file://` and Pages under `/glitchbox/`). Demo clips are real renders: `site/make-demos.sh [TOOLCHAIN]` regenerates them from `site/demos/*.json` chains over synthetic lavfi sources; outputs are committed (`.gitignore` exceptions under `site/assets/`). jj won't snapshot new files over 1 MiB, so keep clips under that. The stack demo uses unseeded frei0r randomness, so rerun once and commit all outputs together.
- `.github/workflows/` — `build.yml` (xcode-27 runner, Xcode 27.0 + Rust 1.97.0 + cargo-about 0.9.2 pinned; swift test, `build.sh all`, DMG artifact; `v*` tag must equal `v$(cat packaging/VERSION)` and creates a draft release) and `pages.yml` (deploys `site/` on release publish or manual dispatch; Pages uses Actions as source, and the `github-pages` environment allows `main` plus `v*` tags, since a release run's ref is the tag). Releasing: bump `packaging/VERSION`, push a signed `v<VERSION>` tag on green `main`, wait for the draft, check the DMG, edit the notes, publish (that deploys the site). The repo is public, so Actions minutes are free; caches are per-branch.
- Licence: Glitchbox's own code is MIT (`LICENSE`). Bundled tools keep theirs (FFmpeg/x264/frei0r/SoX/FFglitch GPL-2.0+, bash GPL-3.0+, ntsc-rs-cli GPL-3.0, GStreamer LGPL); compliance mirrors ntsc-rs: licence texts in the bundle plus credits with source links.

## Commands (verified on aarch64-darwin, macOS 27, Xcode 27)
- `just app` — `packaging/build.sh all`. Cold build compiles ffmpeg/x264/frei0r/SoX/bash/ntsc-rs/bender; ~11 min cold on the CI runner, ~2.5 min warm (app + verify + DMG). Needs Xcode, cargo/rustc ≥ 1.96, cmake, curl, jq; the bundle is ~195 MB (DMG ~92 MB), the build dir ~3.5 GB.
- `just doctor`, `just chain INPUT SEED`, `just verify-repro INPUT SEED`, `just analog|mangle|bend|reactive|sonify ...` — pipelines in the toolchain env (`eval "$(glitchbox env --root . --toolchain build/Glitchbox.app/Contents)"`). `just shell` opens a shell with the toolchain PATH first and the caller's PATH after it; `.envrc` does the same under direnv.
- `just plug validate|list|render --chain NAME|FILE INPUT|export --chain NAME|FILE --format h264|hevc|prores|ffv1|gif|png -o OUT INPUT|clean|env` — CLI built from source against this checkout's library and the `build/` toolchain. `just dev` builds/opens the Debug app (Info.plist `GBDevRoot` = the checkout).
- `cd app/GlitchboxKit && swift test` — engine tests.
- `cd glitch-loop && just base` — full 112 s render (slow). Quick smoke without touching finals: `just loop_s=1 work=/tmp/gl out=/tmp/gl base`.
- xcodebuild must run under `env -i HOME USER PATH=/usr/bin:/bin:/usr/sbin:/sbin` (it imports env vars as build settings; a stray CC/LD/SDKROOT hijacks the build).

## Invariants
- Bit-exactness: all pipeline ffmpeg calls go through `gb_ffmpeg` (bitexact flags are positional — after `-i`). ntsc-rs, bender, and reactive-vcr output (all GStreamer matroskamux, random SegmentUID) is always remuxed; SoX runs with `-D`; ffedit scripts must use seeded PRNG (QuickJS `Math.random()` is unseedable) and read params from `args.params`. `just verify-repro` must stay green. Verified: the first bundled toolchain (VideoToolbox decode) matched the old Nix toolchain — mv-mangle and chain byte-identical, analog-pass and bend frame-identical (`framemd5`). Since the GStreamer allowlist dropped `applemedia`, compressed inputs (H.264/HEVC/ProRes/MJPEG) decode via gst-libav and GStreamer-tool output differs from those renders at ~47 dB PSNR; FFV1 input (the app path) is unchanged.
- Pipeline manifests (schema 2) record `toolchain: {digest, tools}` from `$GLITCHBOX_TOOLCHAIN/Resources/toolchain.json`. The digest is sha256 over `packaging/sources.json` + `packaging/build.sh`, so editing either changes every app cache key and pipeline run ID.
- Tool environment is hermetic (GlitchboxKit `Toolchain`): PATH = `Contents/Helpers` : `<library>/pipelines` : `/usr/bin:/bin:/usr/sbin:/sbin`; only HOME USER LOGNAME TMPDIR LANG LC_* TERM pass through; plus `GLITCHBOX_ROOT`, `GLITCHBOX_TOOLCHAIN`, and toolchain.json `environment` (`FREI0R_PATH` is required — ffmpeg finds no frei0r plugins without it; `GST_PLUGIN_SYSTEM_PATH`/`GST_REGISTRY` isolate GStreamer from `~/.local/share/gstreamer-1.0` and the shared `~/.cache` registry).
- Helpers precede pipelines on PATH, so `reactive-vcr` is the binary; plugin scripts call the pipeline as `"$GB_ROOT/pipelines/reactive-vcr"`, and the pipeline itself resolves the real binary past itself (`type -ap`).
- Pipelines run on macOS userland: BSD sed/od/wc (no GNU flags like `od --endian` or `sed 's/\?//'`), `/sbin/sha256sum`, bundled bash 5 via `#!/usr/bin/env bash`.
- Library layering: user library (`~/Library/Application Support/Glitchbox`, `GLITCHBOX_DATA_DIR`) overlays the built-in one by id/name; saves go to the user library; delete removes only the user copy (reverts an override); builtin-only items can't be deleted. Cache in `~/Library/Caches/Glitchbox` (`GLITCHBOX_CACHE_DIR`).
- App renders are best-effort reproducible (like glitch-loop), not part of `verify-repro`. Cache keys hash the parent key, plugin manifest, resolved params, file/asset digests, and the toolchain digest.
- Intermediates: source prep and every ffmpeg-written layer emit ffvhuff in MKV (lossless, deterministic, 3–4× faster than FFV1 at ~30% more disk). ntsc-rs, bender, and reactive-vcr layers stay FFV1 (remuxed; bender ≥ 0.2.1 and reactive-vcr ≥ 0.4.1 encode it threaded). Layer pix_fmts differ (yuv420p; analog-pass 4:2:0; reactive-vcr yuv444p with source SAR), so every consumer of a layer sets `-pix_fmt` and colour tags explicitly.
- Render settings are Range (whole clip / in–out) plus Resolution (short side, so portrait isn't squashed, or native) plus a rational fps from 23.976/24/25/29.97/30/50/59.94/60 or "match source" (snapped into that set, a whole multiple first so 15 → 30 repeats frames evenly, else nearest by ratio: MPEG-2 mosh rewrites other rates and desyncs). Session schema 2; schema 1 preview/full migrates on load. Source prep crops odd sizes to even (no resample), squares anamorphic pixels (a 90° autorotate inverts SAR), always writes explicit colour tags (probe, else bt709 ≥720 lines / smpte170m), relabels HDR as SDR without tone mapping (the app warns), and keeps `audio.wav` 24-bit for deeper sources.
- Export is a separate final ffmpeg pass over the cached final layer plus the source layer's `audio.wav` (no layer processes audio), so encoder changes never re-render the chain. VideoToolbox `-q:v` is hardware-only; PCM-in-MP4 isn't offered (ffmpeg writes `ipcm`, AVFoundation won't play it). Audio length is `apad` + `-t <probed final-layer duration>`: `-shortest` cut ALAC/PCM 60–75 ms early. Output goes to a hidden partial beside the destination, then `replaceItemAt`; cancel waits for ffmpeg to exit and deletes the partial.
- Proxies (player only): `h264_videotoolbox -b:v 40M`, falling back to libx264 veryfast crf 18 (logged in `proxy.log`).
- glitch-loop is NOT bit-exact-managed (plain ffmpeg/x264); it's an artwork, not a pipeline.
- Packaging gotchas (verified): FFglitch, reactive-vcr, and jq prebuilts are copied byte-for-byte and keep their own linker signatures under ad-hoc signing. reactive-vcr ≥ 0.4 ships as a GStreamer .app; only `Contents/MacOS/reactive-vcr` is copied, and its `@executable_path/../Frameworks/...` rpath lands on our framework — its GStreamer version must match ours (both 1.28.8 now; bump them together). Xcode 27's `strip -S` corrupts chained-fixup Rust binaries, so ntsc-rs-cli/bender ship unstripped. ffmpeg with `--disable-autodetect` needs `-liconv`. SoX 14.4.2 needs two clang fixes (see build.sh). GStreamer devel's own pkg-config is used.
- GStreamer ships only the `GST_PLUGINS` allowlist in build.sh (35 plugins, from `GST_DEBUG=GST_PLUGIN_LOADING:4` traces of all three tools over MKV/MP4/MOV/AVI, FFV1/H.264/HEVC/ProRes/MPEG-4/MJPEG, PNG/JPEG stills, WAV/FLAC/AAC/MP3/Vorbis/Opus). Libraries are the @rpath closure of those plugins, the plugin scanner, and the Helpers binaries (`gst_copy_deps`); the umbrella `GStreamer` binary is an empty stub (nothing links it; the real one re-exports every library). `applemedia` stays out: its `vtdec` fails on ProRes, and software decodes are the same on every Mac. `x264` stays in for H.264 output (`ntsc-rs-cli -c h264`, `bender --codec h264`, reactive-vcr `.mp4`); verify renders all three. Adding a plugin means adding its name to `GST_PLUGINS`; verify fails if any shipped plugin can't load or any dependency doesn't resolve.
- XcodeGen must treat `AppIcon.icon` as a file (`options.fileTypes.icon` in project.yml), or the icon's SVGs get copied into Resources instead of compiled by actool.
- macOS 27.0.1 gotchas in the app: SwiftUI `VideoPlayer` aborts in `_AVKit_SwiftUI` (use the `AVPlayerView` wrapper); `VSplitView` around the player loops AppKit constraint passes and throws; `Slider(step:)` materializes every stop (seed ranges hang the app), so `ParamControl` caps stepped sliders at 1000 stops; a grouped `Form` wrapped in a `VStack` inside `.inspector` makes the split view take its full content height and shifts every column off-screen, so the inspector's Form stays the root and its plugin header is the first section's `header:` (a `.safeAreaInset` header needs its own background, which never matches the Form's).
- App screenshots without input events: write a session.json with `"autoRender": true` into a temp `GLITCHBOX_DATA_DIR` (the app renders a restored auto-render session on launch), `open -g -n --env GLITCHBOX_DATA_DIR=… --env GLITCHBOX_CACHE_DIR=…`, then `screencapture -x -o -l <CGWindowID>`. The site's `assets/app/glitchbox-stack.png` is the `site/demos/stack.json` chain over make-demos.sh's radial `grad.mkv` at 360p, full window scaled to 1400 px.
- Plugin-authoring gotchas (all verified): ntsc-rs `version: 1` presets fill missing keys from `legacy_value()`, not `Default` — `analog-pass` defaults mirror that so they reproduce `presets/vhs.json` exactly (enum values are Rust discriminants, not menu order); analog-pass renders 4:2:0 (`--chroma-subsampling`, recorded in its run ID) and, like all ntsc-rs MKV input, emits one trailing extra frame. ffedit's `-sp` JSON rejects floats, so ffedit-script params must be ints (`scripts/mosh.js` uses percents). The mosh plugins pipe `ffgac … - | ffedit -i - -o - | ffmpeg -f mpegvideo -i -`; MPEG-2 decode is nondeterministic from about frame 17, so their outputs can't be byte-checked. pixel-smear computes its brightness mask once per frame (`colorchannelmixer` → `extractplanes` → `lut`) and uses `geq` only to sample; a per-pixel averaging `geq` was 4.6× slower. `tblend` outputs one frame fewer. ffmpeg's frei0r filter wants bools as `y`/`n` (use enum params). frei0r `colorhalftone` renders solid black. `glitch0r`/`pixs0r` use unseeded randomness.
- FFglitch comes only from the pinned upstream macOS prebuilt in `packaging/sources.json` (never vendor binaries into the repo).

## Platform gaps
Apple silicon macOS only (deployment target 26). No Linux, no Intel, no notarization (ad-hoc signing; `GLITCHBOX_SIGN_IDENTITY` for a real identity, untested).
