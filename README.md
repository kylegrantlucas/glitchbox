# Glitchbox

Glitchbox is a macOS app for breaking video on purpose. You stack plugins into a
chain (datamosh, VHS and NTSC artifacts, circuit-bent video hardware, frei0r and
ffmpeg effects), tweak each layer's parameters, and watch the result in the
built-in player. Every tool the app runs ships inside `Glitchbox.app`, so there
is nothing else to install.

The repo also holds the terminal pipelines the app grew out of. They are seeded
and content-addressed: each run writes a manifest with the input digest, every
resolved parameter, and the toolchain's identity, so an artifact can be
regenerated byte for byte.

Glitchbox needs an Apple silicon Mac with macOS 26 or later.

## Install

Download `Glitchbox-<version>.dmg` from
[Releases](https://github.com/kylegrantlucas/glitchbox/releases), open it, and
drag Glitchbox to Applications.

Builds are ad-hoc signed and not notarized, so Gatekeeper blocks the first
launch. Allow it in System Settings → Privacy & Security → Open Anyway, or clear
the quarantine flag:

```sh
xattr -dr com.apple.quarantine /Applications/Glitchbox.app
```

## Using the app

Pick a source clip, add plugins from the sidebar, and render. The first layer of
every chain is implicit: it trims and scales the clip, converts it to
constant-frame-rate FFV1, and pulls the audio out as `audio.wav`. Each plugin
layer after it hands an FFV1 `.mkv` to the next. Every layer is cached, so
changing one re-renders only that layer and the ones below it.

Chains and per-plugin parameter sets can be saved as presets. Glitchbox ships a
built-in library of plugins and presets, and yours live in
`~/Library/Application Support/Glitchbox`. A plugin or preset there with the same
id or name as a built-in one replaces it. Saving always writes to your folder.
Deleting removes only your copy, so deleting an edited built-in reverts it
("Revert to Built-in"), and a built-in you haven't edited can't be deleted.

| Path | Holds |
|---|---|
| `~/Library/Application Support/Glitchbox/plugins/` | your plugins |
| `~/Library/Application Support/Glitchbox/presets/chains/`, `presets/plugins/<id>/` | your presets |
| `~/Library/Application Support/Glitchbox/session.json` | the last stack, source, and render settings |
| `~/Library/Caches/Glitchbox/layers/` | rendered layers, one folder per cache key |

`GLITCHBOX_DATA_DIR` and `GLITCHBOX_CACHE_DIR` move the first and last of these.
Clear the layer cache with Render → Clear Render Cache… or `glitchbox clean`.

A layer's cache key covers its parent's key, the plugin manifest, the resolved
params, the digests of file params and assets, and the toolchain digest. A failed
layer keeps its log in `<id>-<key>.failed/`. App renders are best-effort
reproducible and aren't covered by `just verify-repro`.

### Built-in plugins

- `analog-pass` exposes every ntsc-rs setting. Its defaults reproduce
  `presets/vhs.json` frame for frame.
- `bender` exposes every bender-rs 0.2 stage and setting, plus stage order. Its
  defaults and presets are bender's bundled ones and match `bend --preset`
  frame for frame.
- `mpeg2-mosh` runs `scripts/mosh.js` (average window, axis scales, drift), with
  presets for sink-and-rise and pan.
- `mv-script` runs the deterministic DD-GlitchAssist ffedit scripts, and
  `mv-mangle` wraps the pipeline of the same name.
- `reactive-vcr` drives VHS artifacts from the source's own audio, or from an
  audio file you pick.
- ffmpeg effects: `vhs-filter`, `trails`, `frame-blend`, `datascope`,
  `rgb-split`, `pixel-smear`, `pixelate`, `bitcrush`.
- frei0r effects: `block-glitch`, `row-shift`, `plasma-distort`, `kaleidoscope`,
  `vertigo`. `block-glitch` and `row-shift` are random, so every render differs
  and the cache keeps the first one.

### Writing plugins

A plugin is a JSON file (`plugins/<id>.json`) that declares typed params and a
list of steps. The plugin editor in the app writes the same format.

An `argv` step runs one command and expands `{in} {out} {work} {root} {params}
{source_audio} {p.<key>}` in its arguments (`{{` and `}}` escape braces). A
`script` step runs under the bundle's bash 5 with `-euo pipefail`, gets
`$GB_IN $GB_OUT $GB_WORK $GB_ROOT $GB_PARAMS $GB_SOURCE_AUDIO $GB_P_<KEY>`, and
isn't template-expanded. `{params}` and `$GB_PARAMS` point at a JSON file of the
resolved, typed params, which is handy for building tool configs with `jq`.
`{root}` and `$GB_ROOT` are the built-in library, where `pipelines/` and
`scripts/` live.

Steps run in a clean environment: the bundled tools come first on PATH, then the
library's `pipelines/`, then `/usr/bin:/bin:/usr/sbin:/sbin`. From your own
environment they keep only `HOME`, `USER`, `LOGNAME`, `TMPDIR`, `LANG`, `LC_*`,
and `TERM`, so a Homebrew ffmpeg can't stand in for the bundled one. `requires`
lists the commands a plugin needs, and the library sidebar names any that are
missing. `assets` are library files whose digests go into the cache key.

Params can set `group` (the inspector section), `labels` (display names for enum
`options`), and `scale: "log"` (the slider favors small values). File params can
set `optional: true`, which passes an empty value through instead of failing.

## Command line

The app carries a CLI at `Glitchbox.app/Contents/Helpers/glitchbox` that uses the
same engine, library, and cache:

```sh
glitchbox list                     # plugins, and whether their tools are present
glitchbox validate                 # check plugins/*.json
glitchbox render --chain analog-mosh-vhs --duration 3 --height 240 in.mp4
glitchbox clean                    # clear the layer cache
glitchbox env                      # the tool environment, as shell exports
```

In a checkout, `just plug ARGS` builds the CLI from source and runs it against
the checkout's library and the `build/` toolchain.

## Terminal pipelines

The pipelines in `pipelines/` run on the tools in `build/Glitchbox.app`, so build
it once with `just app`. Each pipeline prints its output path on stdout and logs
to stderr, so they compose with `$(...)`, and `<pipeline> --help` lists its
knobs.

```sh
just doctor                       # toolchain versions and which pipelines can run
just chain input.mkv 42           # analog-pass, then mv-mangle, then a final encode
just verify-repro input.mkv 42    # run the chain twice and compare every stage
just bend input.mkv 42            # one pipeline: also analog, mangle, reactive, sonify
just shell                        # a shell with the toolchain first on PATH
```

With direnv, the checked-in `.envrc` loads the same environment as `just shell`
once the toolchain exists. Runs land in `out/<pipeline>-<run id>/` with a
`manifest.json`; set `GB_OUT_DIR` to put them somewhere else.

### Reproducibility notes

Each of these broke reproducibility in testing while still producing output that
looked fine:

- ffmpeg's bitexact flags are positional. `-fflags +bitexact` before `-i` binds
  to the input and does nothing for the output, and two runs then differ by 43
  bytes (Matroska's random `SegmentUID` and `DateUTC`). Every pipeline ffmpeg call
  goes through `gb_ffmpeg` in `pipelines/_lib.sh`, which puts the flags after the
  input.
- ntsc-rs, bender, and reactive-vcr render deterministically but write their
  files through GStreamer's matroskamux, which picks a random `SegmentUID`: the
  same seed gives the same frames (checked with `framemd5`) in files whose bytes
  differ. Their pipelines render lossless FFV1 and remux it through `gb_ffmpeg`
  with a stream copy. `bend` also records the fully resolved bender settings
  (`bender --dump-preset` of the preset, every `--set`, and the seed) in the run
  identity.
- SoX dithers by default, and the dither can't be seeded, so `sonify` passes `-D`.
- QuickJS can't seed `Math.random()`. `scripts/mv-shuffle.js` uses its own
  xorshift32 seeded from `-sp`. Upstream scripts in `$FFGLITCH_SCRIPTS` that call
  `Math.random()` aren't reproducible.
- ffedit passes `-sp` params under `args.params`, not as top-level keys on `args`.
  Reading `args.seed` quietly gives `undefined`, which pins every run to the
  default seed while the manifest claims otherwise. ffedit's `-sp` JSON also
  rejects floats, so ffedit-script params are integers.

`just verify-repro` reports per stage, so a regression names the stage that lost
determinism.

## glitch-loop

`glitch-loop/` is a standalone datamosh piece: `source.jpg` gets a judder motion
pass, an MPEG-2 encode with forced motion vectors, a timed `ffedit` smear, and a
VHS filter, and comes out as `out/loop_mosh.mp4`. `just combine VIDEO START LEN
NAME` layers another video over the loop's tail and moshes the two together. It
uses the bundle's ffmpeg and FFglitch with plain x264 encodes, and since it's an
artwork, its output isn't held to bit-exactness.

```sh
cd glitch-loop
just base                                          # full 112 s render (slow)
just loop_s=1 work=/tmp/gl out=/tmp/gl base        # quick smoke test
```

## Building from source

You need Xcode 27, Rust 1.96 or newer (`cargo`, `rustc`), `cmake`, `curl`, `jq`,
and [`just`](https://github.com/casey/just) for the recipes. Everything else is
downloaded from the pins in `packaging/sources.json`, and the build refuses any
file whose sha256 doesn't match.

```sh
just app          # build/Glitchbox.app and build/dist/Glitchbox-<version>.dmg
just dev          # Debug app that uses this checkout's plugins and build/ toolchain
cd app/GlitchboxKit && swift test    # engine tests
```

`just app` runs `packaging/build.sh`. The first run compiles ffmpeg, x264,
frei0r, SoX, bash, ntsc-rs, and bender, and unpacks the GStreamer runtime. Later
runs skip every stage whose recipe and inputs haven't changed. Compilers run
under `env -i` with a short private PATH, so tools from Homebrew or Nix on your
PATH can't end up in the bundle. The build finishes by checking that:

- no binary in the bundle links anything outside `/usr/lib`, `/System`, or the
  bundle itself, and every bundled library resolves;
- ffmpeg (with frei0r), ntsc-rs, bender, and reactive-vcr render test clips,
  covering FFV1, H.264, and PNG inputs and FFV1 and H.264 outputs between them,
  both in place and from a copy of the app in `/tmp`;
- `codesign --verify --deep --strict` passes for the app and for the copy inside
  the mounted DMG.

Set `GLITCHBOX_SIGN_IDENTITY` to sign with a real identity, which also turns on
the hardened runtime. The default is ad-hoc. The version comes from
`packaging/VERSION`.

### What's in the bundle

| Tool | Version | Source |

| [bender-rs](https://github.com/kylegrantlucas/bender-rs) (`bender`) | 0.2.0 | built the same way |
| [reactive-vcr](https://github.com/kylegrantlucas/reactive-vcr) | 0.4.0 | upstream release CLI, run on the bundled GStreamer |
| [GStreamer](https://gstreamer.freedesktop.org) | 1.28.8 | official macOS runtime, arm64 only, cut down to the 35 plugins the tools load (`GST_PLUGINS` in `build.sh`); decodes in software through gst-libav |
| [SoX](https://sourceforge.net/projects/sox/) | 14.4.2 | built from source with two small clang fixes |

The app is about 195 MB on disk and the DMG about 92 MB.
`Resources/toolchain.json` lists these versions, the environment the tools need
(`FREI0R_PATH`, the GStreamer plugin path and registry, and so on), and a digest
of `packaging/sources.json` plus `build.sh`. That digest is the toolchain's
identity in render caches and pipeline manifests.

## Layout

```
app/Glitchbox/          SwiftUI app (app/project.yml is the XcodeGen spec)
app/GlitchboxKit/       engine, glitchbox CLI, and Swift Testing suite
packaging/              build.sh, sources.json (pinned inputs), VERSION
plugins/                built-in plugin manifests
presets/                chain presets, per-plugin presets, vhs.json, reactive-vcr.toml
scripts/                seeded ffedit scripts (mosh.js, mv-shuffle.js)
pipelines/              terminal pipelines and _lib.sh
glitch-loop/            the datamosh loop artwork
site/                   splash page; site/make-demos.sh re-renders its demo clips
build/                  toolchain build output and Glitchbox.app (gitignored)
out/                    pipeline runs (gitignored)
```

## Known gaps

- Apple silicon and macOS only. Linux and Intel Macs aren't built.
- No Developer ID, so no notarization; see Install.
- The Rust tools ship unstripped, because Xcode 27's `strip -S` corrupts
  chained-fixup binaries.
- frei0r `colorhalftone` renders solid black in this build, and `glitch0r` and
  `pixs0r` use unseeded randomness.
